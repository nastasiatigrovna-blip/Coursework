# Рукодельница

Клиент-серверное веб-приложение для продажи изделий ручной работы, схем вязания и видео мастер-классов. Покупатель выбирает в одной карточке один или несколько вариантов («Изделие», «Схема», «Видео»); стоимость рассчитывается автоматически. Карточки создают мастера, а публикуются они после проверки администратора.

## Возможности

- Гость: каталог, поиск, фильтр по категории и сложности, просмотр работ, страница «О нас».
- Покупатель: выбор вариантов работы, корзина, оформление демонстрационного заказа, история заказов и цифровые материалы в личном кабинете.
- Мастер: создание работ, выбор уровня сложности, настройка цены и наличия каждого варианта, просмотр статуса модерации.
- Администратор: одобрение или отклонение работ, управление каталогом, заказами и пользователями.

Поддерживаются пять уровней сложности: начальный, лёгкий, средний, продвинутый и экспертный. Для схем и видео цена может составлять 0 ₽.

## Локальный запуск на Windows

### Требования

- Node.js 20–22 LTS и npm (для деплоя используется Node.js 22; локально можно проверить и на более новой версии);
- PostgreSQL 15 или 16;
- свободные порты 3000, 5000 и 5432.

### 1. Создайте базу данных

В pgAdmin откройте **Servers → PostgreSQL → Databases → Create → Database** и укажите имя `rukodelniza`. Альтернатива через `psql`:

```sql
CREATE DATABASE rukodelniza;
```

### 2. Настройте сервер

Откройте PowerShell в VS Code и выполните:

```powershell
cd F:\coursework\backend
npm install
Copy-Item .env.example .env
```

Откройте созданный `backend/.env` и укажите собственные значения. Пример (не копируйте пароли буквально):

```env
DATABASE_URL="postgresql://postgres:ВАШ_ПАРОЛЬ@localhost:5432/rukodelniza?schema=public"
JWT_SECRET="длинная-случайная-строка-для-локальной-разработки"
PORT=5000
NODE_ENV=development
SEED_ADMIN_PASSWORD="свой-уникальный-пароль-минимум-12-символов"
SEED_MASTER_PASSWORD="другой-уникальный-пароль-минимум-12-символов"
```

Если в пароле PostgreSQL есть символы `@`, `#`, `/` или `:`, закодируйте их в URL. Пароли не публикуйте в GitHub: `.env` исключён через `.gitignore`.

Примените схему и заполните базу:

```powershell
npx prisma generate
npx prisma migrate deploy
npm run prisma:seed
node scripts/add-demo-catalog.cjs
```

Последняя команда создаёт демонстрационные работы и при повторном запуске не добавляет работы с теми же названиями. Запустите API:

```powershell
npm run dev
```

Проверка: откройте `http://localhost:5000/api/health` — сервер должен вернуть JSON со статусом `OK`.

### 3. Запустите клиент

Откройте **второй** терминал VS Code:

```powershell
cd F:\coursework\frontend
npm install
npm run dev
```

Откройте `http://localhost:3000`. Vite перенаправляет запросы `/api` на локальный сервер `:5000`. Оставляйте оба терминала запущенными.

### Тестовые аккаунты

После выполнения `npm run prisma:seed` создаются аккаунты:

| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@rukodelniza.ru` | Значение `SEED_ADMIN_PASSWORD` |
| Мастер | `master@rukodelniza.ru` | Значение `SEED_MASTER_PASSWORD` |

Seed не меняет пароль уже существующего пользователя. Если база не пустая, используйте пароль, с которым аккаунт был создан ранее; не сбрасывайте базу, если в ней есть нужные данные.

### Частые проблемы

- **Сайт не открывается:** проверьте сообщения в обоих терминалах, а также порты 3000 и 5000.
- **Ошибка подключения к базе:** убедитесь, что служба PostgreSQL запущена, база создана и `DATABASE_URL` указан верно.
- **Не работают формы/каталог:** проверьте `http://localhost:5000/api/health` и выполненные миграции.
- **Пустая корзина после обновления версии:** устаревшие записи старого формата удаляются автоматически.

## Развёртывание на Render

В корне проекта находится `render.yaml`: он описывает бесплатный Node.js Web Service и бесплатную PostgreSQL-базу. React собирается в `frontend/dist`, Express отдаёт сайт и API с одного домена.

1. Отправьте код в GitHub (`git push -u origin main`).
2. В [Render Dashboard](https://dashboard.render.com/) выберите **New → Blueprint** и подключите репозиторий.
3. Проверьте планы `free` у сервиса и базы.
4. Задайте `SEED_ADMIN_PASSWORD` и `SEED_MASTER_PASSWORD` (разные, не короче 12 символов). `JWT_SECRET` генерируется автоматически, `DATABASE_URL` берётся из базы.
5. Дождитесь деплоя и проверьте адрес `https://<имя-сервиса>.onrender.com/api/health`, затем главную и каталог.

На бесплатном тарифе Render сервис засыпает после простоя; первое открытие может занять около минуты. Бесплатная база Render действует 30 дней и подходит для демонстрационного проекта, но не для долговременного хранения данных. Для дальнейшего использования потребуется другая база или платный тариф.

**Внимание:** текущая оплата демонстрационная, реальные платежи не проводятся. Цифровые ссылки в демонстрационном каталоге служат примерами, а не готовыми учебными материалами.
